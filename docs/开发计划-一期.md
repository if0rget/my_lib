**目标：** 做出一个接了 PostgreSQL、带登录鉴权的后端 API，能完成注册登录、分类管理、图书的增删改查与搜索分页，全部有自动化测试。

**架构：** `handler → service → repository` 三层。service 只依赖自己包里定义的仓库接口；仓库有两套实现：内存版（给测试用，也是先练手的版本）和 PostgreSQL 版（GORM），用同一组"契约测试"保证两者行为一致。表结构由 golang-migrate 的 SQL 文件管理，服务启动时自动迁移。

**技术栈：** Go 1.27 · Gin · GORM（`gorm.io/driver/postgres`）· golang-migrate · `golang-jwt/jwt/v5` · `golang.org/x/crypto/bcrypt` · `godotenv` · `testify`

**依据：** [docs/项目文档.md](项目文档.md)（功能、数据模型、接口）、[docs/代码规范.md](代码规范.md)（写法约定）。两份都要先读。

## 全局约束

- 模块路径 `github.com/if0rget/my_lib/server`；所有命令在 `server/` 下执行，除非写明 `make`（在仓库根目录）。
- 接口前缀 `/api/v1`；响应体统一 `{ "code": 0, "message": "ok", "data": ... }`；JSON 字段 `snake_case`；时间 RFC 3339。
- 新增成功返回 201，其余成功返回 200；删除成功 `data` 为 `null`。
- 列表响应 `data` 为 `{ "items": [...], "total": N }`；`page` 默认 1（最小 1），`page_size` 默认 20（1–100），越界返回 400。
- 调用方向只能 `handler → service → repository`；service 里不出现 `gin.Context` 和 HTTP 状态码；函数第一个参数是 `context.Context`。
- **字段规则全部在 service 校验**，不合格返回 `service.ErrInvalidInput`；handler 的 binding 只管"JSON 能否解析、必填项、分页范围"。
- 配置只在 `internal/config` 读环境变量；日志用 `log/slog`，不打印密码和 token。
- 表结构只通过 `server/migrations/` 的迁移文件改，不用 `AutoMigrate`。
- 密码用 bcrypt 存；JWT 用 HS256，有效期 24 小时。
- 每个包要有包注释，导出的类型和函数要有注释（`make lint` 会检查）。
- 每个任务结束时 `make check` 必须通过；提交信息 `类型: 中文说明`。

**错误对照表**（`service` 包里定义哨兵错误，`handler.WriteError` 负责转换；`message` 原样返回给前端）：

| service 错误 | HTTP | code | message |
|---|---|---|---|
| `ErrInvalidInput` | 400 | 40000 | 参数错误 |
| `ErrUnauthorized` | 401 | 40100 | 未登录或登录已过期 |
| `ErrBadCredentials` | 401 | 40101 | 用户名或密码错误 |
| `ErrForbidden` | 403 | 40300 | 没有权限 |
| `ErrAccountDisabled` | 403 | 40301 | 账号已被禁用 |
| `ErrNotFound` | 404 | 40400 | 资源不存在 |
| `ErrUsernameTaken` | 409 | 40901 | 用户名已存在 |
| `ErrCategoryNameTaken` | 409 | 40902 | 分类名已存在 |
| `ErrISBNTaken` | 409 | 40903 | ISBN 已存在 |
| `ErrCategoryInUse` | 409 | 40904 | 分类下还有图书，不能删除 |
| `ErrStockBelowBorrowed` | 409 | 40905 | 库存不能小于已借出数量 |

**字段规则：**

| 字段 | 规则 |
|---|---|
| `username` | 3–32 个字符，只能是字母、数字、下划线；区分大小写 |
| `password` | 8–72 **字节**（bcrypt 上限是 72 字节） |
| 分类 `name` | 去掉首尾空格后 1–50 个字符 |
| `title` | 去掉首尾空格后 1–200 个字符 |
| `author` | 去掉首尾空格后 1–100 个字符 |
| `isbn` | 去掉 `-` 和空格后是 10 位（末位可为 `X`）或 13 位数字；**存去掉分隔符后的形式**；不校验校验位 |
| `publisher` | 0–100 个字符 |
| `published_year` | 0（未知）或 1000 到"今年 + 1" |
| `total_stock` | 0–100000 |
| `category_id` | 必须是已存在的分类，否则 `ErrInvalidInput` |

## 评审重点

这些情况文档没有明说，但最容易在实际使用时出问题。每条都已落到对应任务的测试里。

1. **搜索关键词含 `%` 或 `_`**：应当作普通字符匹配，而不是通配符（任务 7）。
2. **空列表**：`items` 必须是 `[]` 而不是 `null`，否则前端 `.map` 会报错（任务 8、9）。
3. **路径里的 id 不是正整数**（`/books/abc`、`/books/0`）：返回 400，不是 500 或 404（任务 9）。
4. **已删除图书的 ISBN 再次录入**：图书是软删除，同一 ISBN 应能重新新增（任务 7）。
5. **超过 72 字节的密码**：明确拒绝（400），而不是被悄悄截断后仍能登录（任务 5）。
