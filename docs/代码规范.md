# 代码规范

能交给工具检查的都交给工具，这份文档只写工具查不了的约定。

## 1. 工具

| 命令 | 作用 |
|---|---|
| `make fmt` | 格式化前后端代码 |
| `make lint` | 检查前后端代码 |
| `make check` | 检查 + 测试，**提交前跑一遍** |

| 范围 | 工具 | 配置 |
|---|---|---|
| 所有文件 | EditorConfig（UTF-8、LF、行尾无空格） | `.editorconfig` |
| Go | golangci-lint（`gofmt`、`goimports`、`govet`、`staticcheck`、`errcheck`、`revive` 等） | `server/.golangci.yml` |
| 前端 | oxlint（检查）、Prettier（格式化） | `web/.oxlintrc.json`、`web/.prettierrc.json` |

## 2. Go

### 命名

- 包名：小写单个单词，不用下划线和复数（`handler`，不是 `handlers` / `book_handler`）。
- 文件名：小写加下划线（`borrow_service.go`）；测试文件 `xxx_test.go`。
- 导出的标识符用 `PascalCase`，未导出的用 `camelCase`；缩写保持同一大小写（`userID`、`HTTPClient`，不是 `userId`）。
- 接口按行为命名，放在**使用方**的包里（`service` 包里定义 `BookRepository` 接口，`repository` 包提供实现）。
- 导出的类型、函数要有注释，以名字开头：`// BookService 处理图书相关的业务逻辑。`

### 错误处理

- 不忽略 error；确实不需要处理时写 `_ =` 并注释原因。
- 向上返回时带上下文：`fmt.Errorf("查询图书 %d: %w", id, err)`。
- 判断错误用 `errors.Is` / `errors.As`，不比较字符串。
- 业务错误定义为包级变量（`var ErrBookNotFound = errors.New(...)`），由 handler 统一转换成 HTTP 状态码和错误码。
- 只在 `main` 里用 `log.Fatal`，其他地方不 `panic`。

### 分层

- 调用方向只能是 `handler → service → repository`，不能跨层、不能反向。
- `handler`：只做解析参数、调 service、返回 JSON，不写业务判断，不直接碰数据库。
- `service`：放业务规则和事务，不出现 `gin.Context` 和 HTTP 状态码。
- `repository`：只做数据读写，不放业务判断。
- 函数的第一个参数传 `context.Context`，一路传到数据库调用。
- 依赖通过构造函数传入（`NewBookService(repo)`），不用全局变量。

### 其他

- 配置只在 `config` 包里读环境变量，其他地方不直接调 `os.Getenv`。
- 日志用 `log/slog`，带键值对：`slog.Info("借书成功", "user_id", uid, "book_id", bid)`；不打印密码和 token。
- 测试用表驱动写法，测试函数名 `Test函数名_场景`。

## 3. 接口

- 路径用小写复数名词，统一前缀 `/api/v1`：`/books`、`/books/:id`。
- 方法语义：`GET` 查、`POST` 增、`PUT` 整体改、`PATCH` 部分改、`DELETE` 删。
- JSON 字段用 `snake_case`；时间用 RFC 3339（`2026-01-02T15:04:05Z`）。
- 统一返回 `{ "code": 0, "message": "ok", "data": ... }`，`code` 非 0 表示业务错误。
- HTTP 状态码要正确：参数错误 400、未登录 401、无权限 403、不存在 404、冲突 409、服务端错误 500。
- 列表接口统一用 `page`、`page_size` 分页，返回 `{ "items": [], "total": 0 }`。

## 4. 数据库

- 表名小写复数加下划线（`borrow_records`），字段名 `snake_case`。
- 每张表都有 `id`、`created_at`；会被修改的表加 `updated_at`。
- 表结构只通过迁移文件改，不手动改库，不用 `AutoMigrate`。
- 迁移文件成对出现（`.up.sql` / `.down.sql`），**已经提交的迁移文件不再修改**，要改就新增一个。
- 涉及多张表的写操作放在事务里。

## 5. 前端

- 组件用函数组件，文件名 `PascalCase.tsx`，一个文件一个组件；其他文件 `camelCase.ts`。
- 不用 `any`；接口的请求和响应类型定义在 `src/api/` 里。
- 请求都经过 `src/api/` 的封装，组件里不直接调 `axios`。
- 服务端数据用 TanStack Query 管理，不手动放进 `useState` 或 zustand；zustand 只放登录状态。
- 能用 Ant Design 组件就不自己写样式。

## 6. Git

- 提交信息格式：`类型: 简短说明`，说明用中文。

  | 类型 | 用途 |
  |---|---|
  | `feat` | 新功能 |
  | `fix` | 修 bug |
  | `docs` | 文档 |
  | `refactor` | 重构（不改行为） |
  | `test` | 测试 |
  | `chore` | 构建、依赖、配置 |

- 一次提交只做一件事；提交前 `make check` 通过。
- 不提交 `.env`、密钥、`node_modules`、构建产物。
